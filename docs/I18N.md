# MelosViz internationalization

Minimal catalog-based i18n (no heavy framework). **Scaffold status:** web has
the widest UI string set; CLI and desktop expose thin en/es catalogs for help /
shell chrome only — not full surface coverage (see WBS-P3.5).

| Surface | Locales | Catalog | Wired today |
|---------|---------|---------|-------------|
| Web | `en` (default), `es` | `web/src/i18n/locales/*.json` | Splash / loading / actions via `t()` |
| CLI | `en` (default), `es` | `backend/src/melosviz/i18n/locales/*.json` | argparse description + subcommand `help=` |
| Desktop | `en` (default), `es` | `desktop/locales/*.json` | window title, titlebar name/tag, skip-link, status Ready |

```ts
// web
import { t, setLocale } from "./i18n";
setLocale("es");
t("action.analyze"); // → "Analizar"
```

```python
# CLI
from melosviz.i18n import t
t("cli.analyze.help")
```

Override at build/runtime with `MELOSVIZ_LOCALE=es` (web, CLI, desktop).
CLI also honors the env var when printing `--help`.

Adding a locale: copy the `en.json` for that surface, translate values, register
in the surface's `index` / `__init__` loader.
